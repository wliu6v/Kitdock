# 共享组件目录

这里放多个工具共同使用的能力，例如配置读取、命令行输出、表格处理。每个组件一个目录，并包含独立 README 与必要测试。

命名建议使用 `<capability>-<language>`，例如 `config-go`、`cli-js`。语言后缀用于识别实现与导入方式；顶层仍按仓库职责组织。

先有真实复用需求再提取组件。公共组件不依赖具体工具，组件之间不得形成循环依赖。不同语言优先共享协议、格式和样例，而不是强制共用内存中的代码。

Go 初期共用根模块；JS 与 Python 使用各自的包管理方式。详细取舍见 [架构方案](../docs/architecture.md)。当前没有已实现共享包。
